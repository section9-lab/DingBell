4C3A 补充翻译调用前的预算与运行存储：默认关闭、原子预留、原成员绑定、配置快照及幂等用量结算。尚未接入翻译接口或模型执行；原文人工回复继续沿用现有流程。具体测试范围见实施进度第 36 节。

4C3B1 在此基础上接入内部 Flue 翻译 Agent 与持久调用许可，验证重启、实例丢失和框架重试不能产生第二次供应商 HTTP。沿用官方 NVIDIA Provider，检查原始响应中的用量字段，原生 HTTP 入口仍关闭。面向用户的翻译接口、结果核对和俄语预览尚待接线；不会因此开启自动客服或真实店铺发送。具体边界见实施进度第 37 节。

4C3B2 接通有原成员绑定的翻译提交/读取接口。服务端选择配置和预算，原 POST 可恢复原回执，GET 不派发模型；等待后的正文再次验权，迟到费用仍记原预算。界面翻译确认、服务端发送来源关联、预算管理和无人读取时的自动核对尚待后续步骤，翻译与真实外发仍分别默认关闭。具体证据见实施进度第 38 节。

4C3B3 接通可编辑俄语预览与显式确认发送；草稿修改后旧预览失效，已提交翻译可按原编号核对，人工改过的译文在当前页面返回编辑或明确拒绝后继续保留。长译文在窄屏输入框内滚动，确认按钮可达。浏览器验收使用隔离的模拟翻译与 Ozon 传输；服务端发送来源关联、完整草稿恢复及真实翻译质量仍待验证，见实施进度第 39 节。

4C3C1 增加首次有效译文的持久快照及原生回执关联，防止后续读取替换已确认依据。迁移 0018 必须先于新版 Worker 执行；冻结失败返回待核对，已发生的用量照常保留。发送命令与此证据的关联仍待下一步接线，见实施进度第 40 节。

4C3C2 接通翻译确认的服务端来源：原预览编号、不可变原译文及人工最终正文哈希进入发送回执和审计投影。重复提交不能更换来源，刷新核对保留原编号；确认不重新调用模型。普通原文发送保持兼容，本片不新增迁移。具体证据和未完成边界见实施进度第 41 节。

4C4 增加人工取消排队回复。取消与发送在同一会话控制对象中判定先后；已开始的请求和未知结果不能取消。最近发送提供明确确认、只读核对和原命令重试；迁移 0019 保留原有尝试与回执并恢复保护触发器。失败重试和平台结果核对仍待后续实现，见实施进度第 42 节。

4C5 为失败、已跳过和已取消的记录补充恢复草稿入口；已有草稿先确认替换，之后仍须预览并确认发送。旧译文候选失效，待核对翻译保留；结果待确认的发送不提供恢复快捷操作。详见实施进度第 43 节。

4D1 增加普通原文草稿的同标签页保存，按账号、成员、公司与会话隔离，刷新或断网重验后恢复。保存失败提示并保留当前输入；已接受发送先清理草稿，再解除原提交核对，避免旧正文复现为新草稿。仅覆盖原文，不包括跨设备或俄语编辑稿，详见实施进度第 44 节。

4D2 增加每会话持久导入顺序、固定导入上界的历史分页及独立追加读取 API；迟到与回填消息按导入序号补读，续页固定本批上界。游标绑定当前成员，每次读取复核授权；客户端校验边界、顺序与重复项。迁移 0020 保留原消息，服务端和客户端合同详见实施进度第 45 节；界面接线由下述 4D3 接续。

4D3 将追加读取接入消息中心，限制当前消息窗口与待显示批次，提供双向历史、较早更新定位、同标签页断线恢复和成员隔离的阅读位置。沿用官方 MessageScroller；普通草稿与发送确认不变。详见架构 11.3E 与实施进度第 46 节。

4D4 分别验证列表周期读取与焦点身份重验后的成员隔离，修正过窄的旧测试假设；消息处理栏压缩长姓名并提供完整姓名弹层，补充发送预览关闭时的焦点后备目标和唯一主内容地标。详见架构 11.3F 与实施进度第 47 节。

4D5 增加公司 IANA 时区设置、版本冲突与结果核对，统一现有工作区时间显示，并补齐其余会话处理弹窗在后台读取时的焦点返回。接口与界面边界见架构 11.3G，验证记录见实施进度第 48 节。

4D6 将消息附带的 SKU / 订单号接到已导入商品和 FBS 包裹，支持拆包分页、来源时间、冲突与缺失状态、读后撤权以及新消息到达时保留选中的订单。详见架构 11.3H 与实施进度第 49 节；真实平台归属语义仍需独立验证。

## 2. 必须先理解的边界

1. Cloudflare 的部署按钮需要云账号、资源开通和必要的密钥；开源不代表云资源和模型调用免费。
2. Ozon 的订单、商品、买家聊天、商品问答、主动建聊是不同能力，必须按店铺权限及履约方式核实，不能互相推定。
3. 平台请求已发出但没有收到结果时，系统必须保留“结果待确认”；队列重试不能代替发送结果核对。
4. 人工接管能阻止尚未开始的 AI 发送；已经进入平台网络请求的消息不能承诺撤回。
5. Flue 的 AI 运行时数据与 DingBell 的业务消息、审计日志分别管理。原始推理轨迹不是消费者消息，也不是默认向客服展示的数据。
6. 本地构建与测试通过不等于云端或业务验收通过；跨阶段验收应分别记录已验证子场景与待复验范围。

## 3. 评审时需要确定的事项

| 编号 | 事项 | 本稿采用的建议 | 对施工的影响 |
| --- | --- | --- | --- |
| D-01 | AI 是否能执行退款、取消和发券 | 首版仅查询、回复、收集资料和转人工；资金与订单变更由人工在平台完成 | 改为自动执行需要增加审批、额度、补偿和平台操作审计 |
