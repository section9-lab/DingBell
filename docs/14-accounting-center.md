# 14. 核算中心（第一版）

入口：工作台 → 订单中心下方的「核算中心」，路由 `/workspace/accounting`。

## 定位与边界

这是基于已同步订单快照的**预估经营分析**，不是平台财务结算账本。默认最近 30 个公司自然日，可选择 7/30/90 天或不超过 366 天的自定义日期，按店铺及 FBS/FBO/FBP 筛选。工作台默认采用明示的当前成本预估模式；店铺、日期、履约方式和成本依据写入 URL，刷新不丢失选择。

- 只计已送达包裹（复用订单中心状态解析，包括 FBP `380`）。取消、退回、运输中和未知状态不确认为收入。
- 沿用订单中心的时间选择逻辑：下单时间优先，其次 FBO 创建时间，最后处理时间；不使用同步时间。时间未知包裹单独提示。
- 当前没有退款、退货损失、物流实际账单、实际广告 API、到账流水、税务、阶梯运费或自动费用分摊。订单详情已接入平台回传佣金费率，但以该费率估算的金额不是已核对结算账单；所有利润均有预估标记。
- 已知销售额独立汇总，不因成本缺失而隐藏；同时显示销售额和采购成本各自覆盖的包裹数量。总成本、利润及利润率在任一包裹资料不完整时为 `—`，不把未知费用当作 0，也不把部分利润冒充整店利润。趋势中未知成本/利润留空，不画成零值。可以另外显示成本完整包裹的预估贡献及其覆盖数量，但该小计不扣整店期间费用，也不能冒充整店利润。整期不完整但有已核算包裹时，卡片和柱状图明确切换为「已核算包裹贡献/贡献率」，贡献率只使用同一已核算子集的销售额作分母。
- 整店期间费用在日期发生当天全额扣除。按履约方式筛选时不分摊期间费用，只计算订单贡献。
- 每次最多读取 1000 个范围内包裹或 1000 条费用。超限要求缩短日期，不静默展示部分总计。

## 页面

1. **经营总览**：销售额、总成本、经营利润、利润率；收入/成本非堆叠 Area Chart；带零基线的利润柱状图；成本构成。
2. **核算明细**：按包裹或商品查看，包裹链接进入订单详情，展开成本来源与缺失项。商品贡献未扣每包裹基础运费、提现和期间费用，不标为商品净利润。
3. **成本与规则**：按影响销售额排序的待补全商品清单，逐项指出采购价/汇率、贴单费和重量缺失；可直接定位商品补录，不必翻遍全部商品。另有版本化成本录入、CSV 导入、费用/汇率版本、期间费用登记和作废。

图表复用 shadcn/ui 组合方式和现有设计 Token，底层 Recharts；启用 accessibilityLayer，提供明细表格，关闭图表装饰动画。表单采用 React Hook Form + Zod，服务端再次验证。查询使用 TanStack Query，不增加全局状态。

## 核算输入与金额精度

- `product_costing`：复用已有表及 `product_name_map`，按当前店铺内唯一商家货号匹配商品（不按名称）。按订单时刻选 `[valid_from, valid_to)` 内版本。
- 首次可录入历史生效日期；之后只能追加更晚的公司自然日版本，更新/插入同一 D1 事务内进行，并保留已有计划字段。
- 采购价币种支持 CNY/RUB/USD/EUR；贴单费、运费及期间费用统一 CNY。重量按单件克数录入。商品资料中的 `product_sourcing` 仍是非版本化的货源参考资料；本版不自动把未知历史价格迁为核算成本，须在核算中心确认价格及其生效日期。
- 规则版本保存 3 种外币→CNY 汇率、佣金费率、提现费率、每公斤运费、每包裹基础运费。佣金费率优先级为：平台对应商品回传费率 → 商品成本模型 → 店铺规则。未使用的外币汇率可以留空；涉及对应币种时才要求补录，不默认按 1 换算。CNY 销售额、CNY 采购及商品已有佣金系数不需要虚构外币汇率。
- 采购、贴单、重量必须完整。无费用须显式录入 0，不能用空白表示 0。
- 金额通过 BigInt 十进制计算，最终四舍五入到人民币分；售价支持最多 12 位小数，不先对单价取整。汇率/商家输入最多 4 位小数。JSON 返回整数分。

```text
销售额 = Σ（平台商品单价 × 数量 × 订单日期适用汇率）
采购 = Σ（单件采购价 × 数量 × 订单日期适用汇率）
贴单 = Σ（单件贴单费 × 数量）
佣金 = Σ（商品销售额 × 平台/商品/店铺佣金费率）
物流 = Σ（单件重量 × 数量 × 每公斤运费）+ 每包裹基础运费
提现 = max(0, 销售额 − 佣金 − 物流) × 提现费率
订单贡献 = 销售额 − 采购 − 贴单 − 佣金 − 物流 − 提现
期间经营利润 = Σ 全部订单贡献 − 当期登记广告费 − 其他期间费用
（任一订单贡献未知则整期经营利润未知，仍独立展示已知销售额及采购金额）
```

## 历史成本与当前参考价

服务端不传模式时严格匹配订单日期的历史版本；工作台默认使用有明确标记的参考价预估，用户也可显式选择严格历史模式。导入时间不等于历史采购日期：今天导入的价格不会自动倒填到上月。配置接口提供全店成本覆盖数量和最早版本日期，页面明确指出缺失原因。

工作台默认并明示「历史缺失时按当前成本预估」，不会要求用户每次刷新后重新点击。仅在找不到当时版本时使用当前未关闭版本，逐包裹标注 `costSource=current_estimate`；不修改成本生效日期，也不允许将该模式冻结为历史事实。已冻结依据不受模式切换影响。未匹配商品仍待补全，物流和提现仍需真实规则，不能以预估模式绕过未知费用。

商品采购参考资料的操作人可能是导入脚本，或账号已删除。缺少操作人关联只显示「导入记录（原操作人不可用）」，不影响整页商品列表和详情读取。

## 已知字段与平台费率

各成本字段独立输出已知小计和覆盖包裹数（`costComponents`）。缺采购的商品不会再把其他商品已有的佣金、贴单金额全部隐藏。收入图可展示「已知成本小计（部分）」虚线，不把它称作完整成本或将两线差值当利润。广告/其他费用没有登记时标为未登记，不称为实际零支出。

FBS/FBO 详情请求开启 `with.financial_data`，FBP 读取已有 `financial_data.products[].posting_commission.percent`。仅保留 SKU（或 FBS product_id）、数量均能唯一对应的费率。新列表没有财务字段时，只在货号、数量、售价、币种都一致的条件下沿用详情费率。模糊或冲突数据不套用。

平台财务金额可能是 RUB，而商品报价是 CNY；本版不将无明确币种的绝对佣金、配送金额与 CNY 采购价直接相加，也不推测汇率。平台观测费率随正常详情同步逐步补齐，不谎称已有全部最终账单。

## 冻结与追溯

`POST /accounting/capture`（总览「冻结当前核算依据」）只冻结当前范围内**成本完整且已送达**包裹的原子输入。GET 无写入副作用。第一版为显式冻结，尚未挂接后台同步自动冻结。当前成本预估模式禁止冻结，服务端同样拒绝，不仅是按钮禁用。

新表 `accounting_posting_basis` 以店铺 + 履约方式 + 包裹号为唯一键，保存采购事实、成本版本 ID、规则 ID 及规则原子输入，不存派生利润。数据库触发器阻止更新，重复冻结不覆盖。相同包裹号的不同履约方式互不串账。商品行身份、数量或归集日期变化时，不继续套用旧依据，而是标为人工核对。平台售价快照仍为只读事实，可以更新，不把冻结称作锁定财务账单。

既有 `posting_cost_snapshot` 保留兼容，不在此链路重复写入；它未包含履约方式及完整汇率/费用规则，不能用它单独复现本版预估。

## 成本 CSV

在「成本与规则」下载**当前商品页**模板（每页 50 个），填写 UTF-8 CSV 后预览、确认。列顺序：

```csv
product_id,offer_id,valid_from,purchase_price,purchase_currency,label_fee,weight_grams
100,offer-100,2026-11-01,5,CNY,0,100
```

以当前店铺的 `product_id` 为权威 ID，`offer_id` 供人工核对，不用于猜测匹配。最多 50 行 / 100 KB；校验日期、金额、重复商品与重量。**逐行保存，允许部分成功**，逐行显示结果，不宣称全批回滚。发生网络不确定结果后先刷新核对，不盲目重试。已有腾讯表归一化脚本仍保留，但其 `sheet_row` 模板需要先完成人工商品 ID 映射，再转换为此模板；不直接按名称导入。

## 权限、费用及接口

- 读取沿用公司及店铺授权；普通成员仅看被授权店铺。
- 写入限 owner/admin，每次最终数据库写入都重查有效会话及管理权限。
- 期间费用使用客户端生成的 UUID 幂等提交；同 ID 不同内容返回冲突。作废保留原内容、录入人、作废人和时间，不能通过重试复活。
- `GET /api/companies/:companyId/accounting`：必填 storeId/fromDate/toDate/fulfillment，日期两端均含。
- `GET .../accounting/config?storeId=...&after=...`：商品按 ID 分页；支持 `productId` 精确定位缺失商品，权限仍按公司/店铺校验；展示最近 10 个规则版本。
- `POST .../accounting/costing`、`rules`、`expenses`、`expenses/void`、`capture`。
